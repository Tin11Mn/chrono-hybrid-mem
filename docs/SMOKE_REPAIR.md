# 冒烟运行故障修复

本次保留8352433及其已取消运行记录，使用独立修复分支。

## 写入锁修复

原Add在SQLite写事务中等待每条消息的模型提取，16个并发请求会在15秒忙等待后
报database is locked。现在先完成模型调用，再通过短写入门一次性原子提交
原文、普通事实、结构化记录及索引。等待模型期间不持有数据库写锁。

同一进程、同一数据库、同一用户/请求ID的重复请求会合并，避免重复模型调用。
最终数据库唯一键再次去重，因此跨进程也不会重复发布；跨进程及失败后重试的
外部模型调用不承诺恰好一次。不同用户复用请求ID不会被静默丢弃，旧去重表
通过事务性迁移保留历史记录。会话/主题分页改为每批受影响组刷新一次。

Add仍然同步；提取失败或发布失败不会提前应答成功，不会留下半条原文/索引。
SQLite忙等待时长没有被简单调大，也不依靠降低平台并发来掩盖锁问题。

## 实际模型协议修复

只使用自造ProtocolSample消息抓取了供应商响应，未读取隐藏答案。发现：

- 普通pending状态被标成update，缺少变更词而被拒绝。模型提示现在明确区分assert
  与update；校验器可把无变更依据的state update/correction保守降为assert，
  不授予覆盖旧值的能力。原文、值、主体、范围及日期见证仍必须通过。
- facts照抄了提示中的short retrieval annotation。提示删除该脚手架，并只过滤
  不在原文中的已知脚手架字面量，不过滤正常有来源的改写。
- 没有evidence_needs时模型照抄need_index0。现在提示按实际需求数量生成索引约束；
  零需求的0仅归一化为一般证据null，不生成任何需求覆盖声明。多需求仍须逐项覆盖，
  未知ID、漏掉必需来源等继续拒绝。
- 带memory_requests对象的规划器不再同时要求所有字段都是数组。
- HTTPS模型代理不再被当作宽容的本地模型端点，非JSON协议错误明确进入失败路径。
