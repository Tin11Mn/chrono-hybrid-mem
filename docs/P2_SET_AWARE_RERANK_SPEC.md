# P2 集合感知重排规格

## 目标

P2 在既有 P1 检索和候选排序之后，改进“有序证据集合”的选择。当一个问题包含多个彼此独立且有用的证据需求时，它应优先让少量、互补的原始证据记录出现在前列。它的目标是在不生成答案、不增加 LLM 调用、也不改变公开 Add/Search API 的前提下，减少前排结果中重复的同一跳证据。

首个实现是可选的本地研究能力，并不宣称能够提升排行榜。只有在公开数据或合成的能力分层上完成评测后，才可以考虑用于平台提交。

## 假设与非目标

- P1 会产生受边界约束的结构化计划，包含 `core_terms`、`entities`、`temporal_cues`，以及最多四项 `evidence_needs`。
- 现有的一阶段检索与候选排序器仍是候选相关性的唯一来源；P2 不检索或虚构新证据。
- 证据需求文本是衡量互补性的、范围受限的查询侧代理信号，但不是标准答案或基准标签。
- P2 不实现图谱遍历、查询改写、答案生成、按数据集定向路由，也不增加模型推理调用。

## 项目结构

- `app/storage.py`：构建最终的、有边界的证据顺序，并记录检索轨迹。
- `app/main.py`：解析默认关闭且有边界的环境变量，并将其传给 `MemoryStore`。
- `tests/test_set_aware_rerank.py`：P2 的确定性单元测试和集成测试。
- `tests/test_model_mode.py`：配置及应用接线测试。
- `evaluation/`：未来的公开/合成能力分层和成对评测适配器；不得加入私有排行榜输入或答案标签。

## 设计

### 功能开关与边界

- `MEMORY_SET_AWARE_RERANK=false` 为默认值。
- P2 要求 `MEMORY_STRUCTURED_QUERY_PLAN=true`；否则启用时必须快速失败。
- 输出候选的 ID 和内容必须是 P2 之前有序候选 ID 的稳定重排或子集。`top_k`、模型重排上限、精确 `user_id` 隔离和模型调用次数均不改变。
- 如果 P1 没有产出可用证据需求、候选少于两条，或计划无效，P2 必须原样返回 P2 之前的顺序。

### 选择契约

针对既有的有序候选，P2 每一步按照以下元组的最大值确定性地选择下一项；若相同，则按原始排名打破平局：

1. 候选是否覆盖当前尚未覆盖的证据需求词；
2. 新覆盖的、规范化后需求词数量；
3. 候选的原始排名。

覆盖必须是词法且来源局部的：一个需求先使用现有查询词规范化器进行规范化；只有当该需求至少一个规范化词元出现在候选的原始内容或现有的来源关联注释中时，该候选才算覆盖该需求。P2 不会构造新文本或新的语义边。一旦所有剩余候选都无法新增覆盖，剩余候选必须保持原有相对顺序。

因此，当所有候选覆盖相同时，输出会保留决定性最高排名证据；当一条互补来源记录覆盖了不同的已声明需求时，它可以提前。

### 检索轨迹契约

启用 P2 时，`last_retrieval_trace` 只能记录由既有候选和冻结查询计划导出的诊断信息：

- `p2_enabled`；
- P2 前后的候选 ID 顺序；
- 规范化后的证据需求词元；
- 每个已选候选新增覆盖的需求词元。

轨迹不得包含答案文本、标准答案标签、基准名称、生成证据或跨用户记录。

## 测试策略

1. 对相同数据库和模型，开关关闭时的行为必须与 P1 字节级/顺序级一致。
2. 空或无效的证据需求，以及只有一条候选的情形，必须保留原顺序。
3. 双需求夹具必须能把第二条互补原始消息排在冗余同需求消息前，同时不改变 ID、内容、用户隔离、候选池大小或调用次数。
4. 平局必须保留原顺序；不能带来新增覆盖的候选必须保留原有相对顺序。
5. 轨迹必须是确定性的，且只包含已有 ID 和由计划导出的词元。
6. 当结构化规划关闭时，配置必须拒绝启用 P2；开关关闭时不得因无效的 P2 配置而失败。
7. 效果评测分阶段进行：先做固定 20 题机械检查；再做显式召回、多跳、时序、偏好、治理和安全等公开/合成能力分层；只有通过预先声明的非退化门槛，才进入固定 200 题本地代理评测。

## 边界

- 始终执行：保留原始来源证据、精确 `user_id` 过滤、有边界的候选池、确定性平局规则，以及零额外模型调用。
- 需要先询问：数据库模式变更、新依赖、CI 变更、改变默认行为、外部基准提交，或运行付费/远程模型。
- 禁止：用私有基准输入、基准身份、参考答案或模型生成的答案文本选择 P2 行为；提交凭据、模型权重或评测数据。

## 成功标准

- P2 默认关闭且配置安全。
- 开关关闭时，P1 的顺序和调用次数不变。
- 开关开启时，P2 只能基于冻结的结构化计划和现有记录，进行确定性的、保留来源的重排。
- 聚焦测试及既有相关回归套件通过。
- 在任何带结果的本地模型运行前，固定 20 题机械报告不得出现契约违例；只有多分层结果为正，才可以主张其具有跨数据集潜力。

## 待定问题

固定 200 题的具体升级阈值，以及公开/合成分层的组成，必须在第一次带结果的运行前声明；此前应先由实现产生可测量的 P2 检索轨迹诊断。

## 已声明的评测升级门槛

- 固定 20 题只用于验证 P2 成对运行的机械正确性和方向性，不作为跨数据集或排行榜结论。
- 每题两个 arm 必须复用同一冻结计划、同一准备数据库、同一候选重排模型；每 arm 恰好一次计划读取和一次候选排序；数据库摘要、P1 一阶段轨迹及 P2 的“仅重排”审计必须全部通过。
- 固定 20 题若 Hit@1 或 MRR 任一低于 P1，则停止该配置，不进入更大规模本地代理运行。若两项均不低于 P1，才进入公开/合成的显式召回、多跳、时序、偏好、治理与安全分层；这一步仍不是提交资格。
- 只有所有分层均不退化，且固定 200 题相对 P1 的 Hit@1 和 MRR 均不低于零、Hit@1 的逐题胜场不少于负场，才允许将 P2 作为“值得保留的本地代理候选”记录。任何平台提交仍须在独立的官方测评中确认。
