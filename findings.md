- A 2026 training-free study evaluates the same LoCoMo conversations at **session level**, not exact evidence-turn level. It reports BM25 Hit@1 0.640, BGE-large max-turn dense 0.602, fused BGE-large 0.721, and fused e5-large-v2 0.752. The method scores each session with the maximum query-to-turn cosine, z-fuses that with session BM25, and selects alpha by leave-one-conversation-out validation.
- The large gap between that paper's session-level BGE-large fusion 0.721 and this project's exact-turn 0.4355 suggests the next controlled change should be hierarchical retrieval: rank sessions with max-over-turn dense plus session BM25, then rank original turns only inside the best sessions. This directly preserves the stricter output contract instead of comparing incompatible metrics.
- Nano-Memory (arXiv 2604.11628) attributes gains to Turn Isolation Retrieval and Query-Driven Pruning. LongMemEval (arXiv 2410.10813) independently identifies session decomposition, fact-augmented keys, and time-aware query expansion as useful memory design choices. APEX-MEM (arXiv 2604.14362) adds append-only entity/event structure and query-time temporal resolution but depends more heavily on an agentic LLM.
- For a local, leakage-safe next ablation, hierarchical session-to-turn retrieval is lower-risk and more directly evidenced than adding another generic token-level reranker. E5-large-v2 is the most promising encoder change after hierarchy because it led the paper's six-encoder comparison.
- The current LoCoMo evaluator flattens every source session into one `AddRequest` and assigns a single synthetic `session_id` to the entire conversation, even though each message retains the session number only as `event_ts`. This prevents `MemoryStore` from testing session-level retrieval at all. Preserving the dataset's original session boundaries in separate Add calls is an API-realistic evaluator correction; the v0.2 lexical comparison should remain numerically unchanged because its query ignores `session_id`.
- `raw_messages` already stores `session_id`, so a hierarchical experiment can remain API-compatible: maintain a Porter FTS document per `(user_id, session_id)`, compute max query-turn dense score per session, z-fuse the session lexical/dense scores, and feed the session signal back into original-turn ranking. No gold evidence or QA label is needed at retrieval time.
- On the fixed 200-question prefix with BGE-large and turn fusion alpha 0.3, hierarchical session weights 0/0.25/0.5/1/2/4 produced Hit@1 0.395/0.400/0.415/0.415/0.420/0.405. Weight 2 is best for Hit@1 (+0.025), while weight 0.5 gives the best Hit@10 at 0.830 versus 0.775 flat.
- The session signal is helpful but not sufficient: strong weights trade away deep recall, and category gains are uneven. Test it jointly with the already validated top-5 token-level reranker before deciding whether to retain the hierarchy.
- Combining session weights 0/0.5/1/2 with ColBERT-small top-5 produced 200-question Hit@1 0.440/0.430/0.425/0.425. Hierarchy improved Hit@3/10 and sometimes MRR but consistently reduced the primary Hit@1 metric after hard ColBERT reranking, so it is rejected from the default path.
- The current ColBERT stage is an all-or-nothing reorder: it discards the calibrated lexical/dense/session score inside the top-5 pool. A safer next ablation is score-level fusion between the existing fused score and ColBERT MaxSim, with weight 0 recovering the first-stage order and weight 1 recovering hard reranking.
